# lknpd

[![npm](https://img.shields.io/npm/v/lknpd)](https://www.npmjs.com/package/lknpd)
[![CI](https://github.com/varrcan/lknpd/actions/workflows/ci.yml/badge.svg)](https://github.com/varrcan/lknpd/actions/workflows/ci.yml)
[![license](https://img.shields.io/npm/l/lknpd)](LICENSE)

TypeScript-клиент неофициального API [«Мой налог»](https://lknpd.nalog.ru/) для самозанятых:
регистрация доходов (чеков), аннулирование, поиск и печатная форма.

- Ноль runtime-зависимостей: Node ≥ 20, bun, серверный рантайм Next.js; ESM и CommonJS.
- Ошибки различают «запрос точно не ушёл», «мог дойти» и «сервер отказал» — основа защиты от
  двойного чека.
- Поиск ранее созданного чека по отпечатку — для сверки после сетевого сбоя.
- Деньги — строкой или целыми копейками, без float; время чека — в поясе самозанятого.

> [!WARNING]
> API неофициальный: ФНС может изменить его без предупреждения. Держите ручной путь пробития
> чека запасным. До `1.0.0` публичный API пакета может меняться в минорных версиях (semver 0.x).

## Установка

```sh
npm install lknpd
# или: pnpm add lknpd / bun add lknpd
```

## Быстрый старт

```ts
import { LknpdClient, MemoryTokenStore } from 'lknpd';

const client = new LknpdClient({
    deviceId: 'shop-backend-1', // стабильный, свой на каждый сервис
    timezone: 'Europe/Moscow', // IANA-зона самозанятого
    tokenStore: new MemoryTokenStore(),
    credentials: { inn: process.env.NPD_INN!, password: process.env.NPD_PASSWORD! },
});

const receipt = await client.createIncome({
    items: [{ name: 'Подписка Pro, 1 месяц', amount: '149.00' }],
    operationTime: paidAt, // момент оплаты
});

console.log(receipt.receiptUuid, receipt.printUrl);
```

Вход выполняется сам при первом вызове, токен обновляется заранее (за 60 с до истечения) и при
ответе 401. Явный вход: `loginWithPassword()`, по SMS — `requestSmsCode(phone)` →
`loginWithSms({ phone, challengeToken, code })`.

### Методы

| Метод                                                | Что делает                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| `createIncome({ items, operationTime? })`            | регистрирует доход (покупатель — физлицо, юрлицо, иностр.) |
| `cancelIncome({ receiptUuid, reason })`              | аннулирует: `'refund'` (возврат) или `'mistake'` (ошибка)  |
| `listIncomes({ from?, to?, limit?, … })`             | страница чеков, `limit` 1–100, `hasMore`                   |
| `findIncomes({ operationTime, totalAmount, names })` | все чеки с этим отпечатком, включая аннулированные         |
| `getReceipt(uuid)`                                   | данные чека                                                |
| `receiptPrintUrl(inn, uuid, base?)`                  | ссылка на печатную форму, без сети и сессии                |

Суммы: строка рублей (`'149'`, `'149.9'`, `'149.90'`) или `{ kopecks: 14990 }`. Количество —
целое ≥ 1. В моделях ответов суммы — строки `'N.NN'`, время — `Date`, ответ целиком — в `raw`.

## Конфигурация

| Опция            | По умолчанию                 | Зачем                                                       |
| ---------------- | ---------------------------- | ----------------------------------------------------------- |
| `deviceId`       | — (обязательна)              | «устройство» в ФНС; стабильно между рестартами и подами     |
| `timezone`       | — (обязательна)              | пояс, в котором формируется время чека                      |
| `tokenStore`     | `MemoryTokenStore`           | где живёт сессия                                            |
| `credentials`    | —                            | ИНН и пароль для входа, в том числе при отозванном refresh  |
| `baseUrl`        | `https://lknpd.nalog.ru/api` | например, свой прокси                                       |
| `receiptBaseUrl` | `https://lknpd.nalog.ru/api` | база ссылок для покупателя; от `baseUrl` не зависит         |
| `fetch`          | `globalThis.fetch`           | свой транспорт, прокси, тесты                               |
| `timeoutMs`      | `30000`                      | предел на весь вызов, соблюдается и в bun                   |
| `userAgent`      | Chrome                       | если ФНС начнёт отсекать устаревший                         |
| `onRequest`      | —                            | хук для логов: метод, путь, статус, длительность, `outcome` |

Пароль и токены не попадают ни в ошибки, ни в `onRequest`.

## Свой TokenStore

Сессия хранится у вас: пакет не пишет файлов. Храните её как пароль: refresh-токен ФНС не
ротирует и не отзывает при новых входах, так что утёкшая сессия даёт долгий доступ к кабинету.
Для нескольких процессов — общий стор (Redis, БД) и межпроцессная блокировка вокруг
обновления токена:

```ts
import type { Session, TokenStore } from 'lknpd';

const store: TokenStore = {
    async load() {
        const raw = await redis.get('npd:session');
        return raw ? (JSON.parse(raw) as Session) : null;
    },
    async save(session) {
        await redis.set('npd:session', JSON.stringify(session));
    },
    // Необязательно: внутри блокировки пакет перечитывает стор и обновляет токен
    // только если его ещё не обновил другой процесс.
    async withRefreshLock(fn) {
        return withRedisLock('npd:session:lock', fn);
    },
};
```

Внутри одного процесса одновременные вызовы и так делят одно обновление.

Под `withRefreshLock` пакет выполняет до двух HTTP-запросов подряд — обновление токена и вход
по паролю или обмен SMS-кода и запрос профиля, — то есть до 2 × `timeoutMs` (60 с по
умолчанию) плюс операции стора. Срок блокировки и ожидание её у других процессов должны это
покрывать. Если блокировка всё же истечёт и два процесса войдут одновременно: вход с другого
`deviceId` чужие сессии не выбивает (проверено в пределах жизни токена, ~1 ч), а два входа с
одного `deviceId` — поды одного сервиса — не проверены.

## Ошибки

Каждая ошибка — `LknpdError` с полями `kind` и `outcome`. Проверка — `isLknpdError(e)`
(работает и при двух копиях пакета в дереве).

| `outcome`    | Что значит                           | Примеры                                          |
| ------------ | ------------------------------------ | ------------------------------------------------ |
| `not-sent`   | запрос до ФНС не дошёл               | DNS, отказ в соединении, неверные входные данные |
| `maybe-sent` | запрос мог быть обработан            | таймаут, обрыв, 5xx, 200 с непонятным телом      |
| `rejected`   | ФНС обработала и отказала — чека нет | 4xx, 401 после обновления токена                 |

`kind`: `network`, `timeout`, `http`, `auth`, `validation`, `protocol`. Для HTTP-ошибок есть
`status`, а также `code` и `fnsMessage` из ответа ФНС.

`kind: 'auth'` у любого метода значит «не удалось войти или токен отвергнут»: 401 на любом
запросе либо отказ 4xx (кроме 429) внутри входа — по паролю, обновления токена, SMS-входа
вместе с запросом профиля, — явного или автоматического перед вызовом. Прочий `rejected` —
отказ по существу самого вызова. 429 остаётся `kind: 'http'`: это временное ограничение; на
429 при обновлении токена пакет не пробует войти по паролю.
Сбой входа (5xx, таймаут) перед вызовом даёт `not-sent` с исходным `kind`.

## Пробитие без двойных чеков

У API нет ключа идемпотентности: повтор после сбоя может создать второй чек. Рецепт (подробнее
о подходе — [статья на Хабре](https://habr.com/ru/articles/1065464/)):

1. **Захват.** Атомарно переведите оплату в `processing` в своей БД (например,
   `UPDATE … WHERE status = 'pending'`) — один воркер на оплату.
2. **Создание.** Вызовите `createIncome` с `operationTime` = момент оплаты. Отпечаток чека —
   этот момент (до секунды), сумма и наименования позиций; всё это известно и сохранено у вас
   ещё до вызова.
3. **Ветвление по `outcome`:**
    - успех → сохранить `receiptUuid`, статус `done`;
    - `not-sent` → чека нет, повторить позже;
    - `rejected` и `kind: 'auth'` → чека нет, но сломан вход (пароль, блокировка): остановить
      пробитие всей очереди и позвать человека — оплата не виновата;
    - `rejected` со статусом 429 → чека нет, подождать и повторить;
    - прочий `rejected` → отказ по этому чеку: повторить после исправления причины, см.
      `fnsMessage`;
    - `maybe-sent` → статус `unknown`, перейти к сверке.
4. **Сверка.** Через минуту-другую вызовите `findIncomes` с тем же отпечатком: 0 совпадений —
   пробить заново, 1 — принять его `receiptUuid`, больше одного — к человеку.

```ts
import { isLknpdError } from 'lknpd';

const operationTime = payment.paidAt; // фиксируется до вызова
try {
    const r = await client.createIncome({ items, operationTime });
    await markDone(payment, r.receiptUuid);
} catch (e) {
    if (!isLknpdError(e) || e.outcome === 'maybe-sent') await markUnknown(payment);
    else if (e.kind === 'auth') await pauseQueueAndAlert(payment, e);
    else await markRetry(payment, e);
}

// позже, для unknown:
const found = await client.findIncomes({
    operationTime,
    totalAmount: payment.amount,
    names: items.map(i => i.name),
});
```

Отпечаток различает чеки с точностью до секунды: две оплаты с одинаковыми суммой и
наименованием в одну секунду неразличимы — такие случаи сверка отдаёт человеку (больше
одного совпадения).

## Несколько сервисов одного самозанятого

- Каждому сервису — свой постоянный `deviceId`. ФНС блокирует «устройство», под которым
  ходят много пользователей, а случайный `deviceId` на каждый под плодит устройства.
- Сервисы друг другу не мешают: вход с одного `deviceId` не выбивает сессии других — ни
  сервисов, ни веб-кабинета в браузере (проверено). Каждому сервису можно держать свой стор.
- Подам одного сервиса — общий `TokenStore` с `withRefreshLock`: иначе каждый под входит и
  обновляет токен сам.
- Привязан ли токен к IP, не проверено. Получайте сессию там же, где её используете, — не
  переносите её с локальной машины в кластер.
