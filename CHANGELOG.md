# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
До `1.0.0` публичный API может меняться в минорных версиях.

## [0.1.0] — 2026-10-07

Первый выпуск.

### Добавлено

- `LknpdClient`: вход по ИНН и паролю, по SMS (два шага); автоматическое обновление токена
  (за 60 с до истечения и по 401) с одним обновлением на процесс и необязательной
  межпроцессной блокировкой `TokenStore.withRefreshLock`; `MemoryTokenStore`.
- Чеки: `createIncome` (деньги в копейках без float, время в поясе самозанятого через `Intl`,
  покупатель — физлицо, юрлицо или иностранная организация), `cancelIncome`, `listIncomes`,
  `findIncomes` — поиск по отпечатку для сверки после сбоя.
- Документы: `getReceipt`, `receiptPrintUrl` — публичная ссылка на печатную форму.
- `LknpdError` с `kind` и `outcome` (`not-sent` / `maybe-sent` / `rejected`), `isLknpdError`
  без `instanceof`; секреты в ошибки и хук `onRequest` не попадают.
- ESM + CommonJS, ноль runtime-зависимостей; Node ≥ 20, bun, серверный рантайм Next.js.

### Проверено на живом API

Вход (`username`), независимость сессий разных `deviceId`, refresh без ротации,
чтение списка и JSON чека, публичная печатная форма, ответы 4xx; сквозной прогон собранного
пакета (ESM и CJS) — только чтение.

### Не проверено

Живые проверки, требующие настоящей оплаты, возврата или второго IP, ещё не выполнены:

- возвращается ли в списке та же секунда `operationTime`, что отправлена, и виден ли чек
  сразу после создания — от этого зависит надёжность `findIncomes`;
- по какому времени (`operationTime` или `registerTime`) фильтруется список;
- форма ответа аннулирования и `cancellationInfo` — по стороннему справочнику;
- привязан ли токен к IP.
